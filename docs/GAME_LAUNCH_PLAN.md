## WITHERROOT 完善计划

当前已有五关渐进主线、关后遗物、刷新保留长期进度，以及指定手机/横屏尺寸的浏览器流程记录。现有改版报告也明确写明：还没有重新邀请真实玩家试玩；首关到第二关之外的全流程平衡和设备覆盖尚未形成发布证据。

### 阶段 1：补齐主线发布验证

- 从新存档走完五关，覆盖胜利、失败、重试、领奖、下一关解锁、刷新和重进；确认进度、遗物只结算一次且不会丢失。
- 校对关卡目标、提示与实际规则，确认后续关卡不是只解锁但无法完成。
- 验收：一名未看说明的测试者可独立开始并完成至少前两关；五关均有可复现的通关路径；存档边界清楚。

### 阶段 2：小规模试玩与设备覆盖

- 邀请 5–8 名首次玩家，观察他们能否理解生长、灰烬、记忆节点、霜冻和遗物，不在过程中提示答案。
- 在窄屏竖屏、短屏横屏和桌面视口检查棋盘、奖励弹窗、语言切换、设置和触控；验证第三方 SDK 被拦截时游戏仍可开始和完成。
- 验收：没有阻断流程的问题；记录并修复重复出现的理解障碍；未通过的尺寸/浏览器有明确限制说明。

### 阶段 3：开放试玩

- 修订新手提示和关卡难度后，再更新作品集卡片、封面与游戏简介。
- 验收：从作品集卡片可直接进入；主线结束后可重玩或回菜单；已知问题和支持设备范围写清楚。

## STELLAR FORGE 完善计划

当前入口 HTML 含有 `history.replaceState(..., "/")`，进入游戏后会把地址改到站点根路径；刷新或分享时可能无法回到游戏。它还会预先把教程标为已看，并由 `progressive-flow.js` 根据页面按钮文字自动点击跳过剧情/继续，容易绕过真实教程且依赖界面文案。

### 阶段 1：移除发布阻断项

- 用稳定的子路径处理资源和地址，删除把地址重写到 `/` 的逻辑；验证深链接、刷新、返回和分享链接都回到游戏。
- 删除“预先标记教程已完成”的写入；把五波提示整合进游戏自身流程，移除依赖 DOM 文案的自动跳过和点击。
- 验收：首次访问必定能看到并完成教程；关闭提示、刷新或重新进入不会偷偷跳过剧情，也不会离开游戏路径。

### 阶段 2：完成一局与设备验收

- 从新存档完整试玩五波和首领战，覆盖元素切换、融合、技能、胜负结算、重开和存档恢复；检查提示触发是否与实际机制一致。
- 测试手机触控和窄屏布局；Google Fonts 不可用时确认字体回退正常。
- 验收：首次玩家能独立完成一局；无卡死、失效按钮或刷新丢失；不同屏幕下主棋盘和操作按钮均可用。

### 阶段 3：开放试玩

- 至少 5 名新玩家完成无提示试玩；根据误解点调整教程、敌人节奏和首领难度。
- 验收：新玩家能说明投放、自动攻击、融合和元素克制的基本关系；所有阻断级问题清零后再加入游戏页。

## 共用上线门槛

- 每款游戏从作品集入口开始可玩，刷新、返回和直接访问深链接正常。
- 中文/英文页面文案、结局数、封面和实际玩法一致。
- 至少覆盖桌面和常见手机视口；没有遮挡主操作的弹窗或横向溢出。
- 上线前完成一次真实玩家试玩记录；试玩只用于发现明显阻碍，不把小样本结果表述为留存或转化结论。
